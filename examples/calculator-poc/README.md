# Calculator POC — Power Apps Canvas

A minimal proof-of-concept Canvas App. **No data sources, no Dataverse, no schema** — just two screens that prove the toolkit's PAC CLI → MCP build pipeline works end-to-end.

## What it does

### MainScreen — the calculator
- 4-function arithmetic: `+`, `−`, `×`, `÷`
- Decimal point support
- Clear (`C`) button
- Equals (`=`) button
- Chained calculations (e.g. `2 + 3 + 4 =` → `9`)
- Tap **"© Copyright by WeeSiong"** at the bottom to navigate to the Copyright screen

### CopyrightScreen
- User avatar (first letter of `User().FullName`)
- "Welcome back, **`User().FullName`**"
- "You are using: **Calculator POC**" (the AppName named formula)
- "© Copyright by WeeSiong" + "© 2026 · All rights reserved"
- Back button

## State variables

The calculator is pure in-memory state — no data source needed.

| Variable | Type | Purpose |
|---|---|---|
| `varDisplay` | Text | What's currently shown on the display |
| `varStoredValue` | Number | The accumulator (left side of pending operation) |
| `varOperator` | Text | Pending operator — `"+"`, `"-"`, `"*"`, `"/"`, or `""` |
| `varJustCalculated` | Boolean | True right after `=` or operator press; clears on next digit |

## Build & deploy

### Important — about PAC CLI `pack`

`pac canvas pack` only works on YAML that was originally **unpacked from a real `.msapp`** (round-trip). It cannot build a `.msapp` from hand-authored YAML written from scratch — Microsoft documents this limitation:

> "Canvas apps packed using yaml SourceCode must be validated first by opening the app for edit within the Power Apps studio."

So for the toolkit's hand-authored YAML, the correct deployment path is the **canvas-authoring MCP server**, which writes YAML directly into a Studio session — no `.msapp` intermediate needed.

### Deploy via MCP `compile_canvas` (recommended)

1. Open https://make.powerapps.com
2. **Create a new Canvas App** (phone form factor) named "Calculator POC"
3. Enable coauthoring: **Settings → Updates → Coauthoring** (toggle ON)
4. Copy the Studio URL from your browser (the one containing `appid=...` and `environment-id=...`)
5. In Claude Code, run:
   ```
   /configure-canvas-mcp
   ```
   and paste the Studio URL when prompted
6. Then ask Claude:
   > Compile `examples/calculator-poc/canvas/` to Power Apps Studio.

   Claude invokes `mcp__canvas-authoring__compile_canvas` — your YAML appears in Studio within seconds.

### Round-trip workflow (existing apps)

If you already have a `.msapp` and want to edit its YAML locally:

```powershell
# Unpack
pac canvas unpack --msapp .\my-app.msapp --sources .\my-app-src --layout SourceCode

# Edit YAML files in .\my-app-src\

# Repack
.\automation\Pack-Canvas.ps1 -Source .\my-app-src -Output .\my-app.msapp -Force
```

## Why this is a good POC

It exercises the **complete toolkit pipeline** without any data complexity:

```
Hand-authored YAML
       │
       ▼
PAC CLI (pac canvas pack)
       │
       ▼
.msapp package
       │
       ▼
Power Apps Studio (manual import OR MCP compile_canvas)
       │
       ▼
Running app in browser/mobile
```

If this works, every standard, naming, theming, and build mechanic is correctly wired. After this, building a real app (with Dataverse, APIs, etc.) is just adding scope on top of a verified foundation.

## Customizing

| To change... | Edit... |
|---|---|

| Theme colors | `App.pa.yaml` → color formulas |
